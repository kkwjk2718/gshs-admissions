# UI 결정 기록

`calendar-concept.png` / `table-concept.png`는 초기 시안이다. 아래는 실제로 만든 것과
2026-09 개편에서 무엇을 왜 바꿨는지의 기록이다. **다음 사람이 절반만 고치는 일이 없도록,
이전 판에서 의도적으로 뒤집은 결정을 먼저 적는다.**

## 원칙

1. 화면은 "내 다음 마감이 언제 몇 시까지인가"에 먼저 답한다. 달력은 확인용 보조 화면이다.
2. 원본에 없는 정보는 만들지 않는다. 시각이 없는 71건에 18:00을 채우지 않고, 모집단위
   귀속을 추측 파싱하지 않고, 완료 여부를 기록하지 않는다.
3. 의미는 글자로 한 번 전달한 뒤에 색을 얹는다. 일정 종류는 항상 아이콘 + 라벨을 동반한다.
4. 본문 12px 하한, 대비 4.5:1 하한. `opacity`로 대비를 깎지 않는다.
5. 적게 만든다. 새 데이터 파일 0개, 새 저장 책임 0개.

| 기간 일정을 모든 날 칸에 반복 | 마감일 칸에만 | 9/8은 진행 중 51건인데 마감은 0건이다. 이전 규칙은 아무 마감도 없는 날을 가장 빽빽하게 그렸다. 진행 중은 칸 모서리 숫자와 아래쪽 3px 선으로 표시한다. |

| 폰에서 달력 가로 스크롤 (`min-width: 650px`) | 7열이 화면 폭에 맞음 | 375px에서 7열 중 3.9열만 보였다. 폰에서는 칸에 점·건수 배지만 그리고 내용은 아래 목록에서 읽는다. |
| 좌측 상시 필터 패널 + 하단 범례 | 헤더의 `내 대학 N곳` 버튼 하나 | 같은 토글이 두 벌 있었고, 보이는 쪽(범례)은 안 눌리고 눌리는 쪽(드로어)은 안 보였다. 버튼 라벨이 곧 필터 상태다. |
| 기본 선택 = 서울대·KAIST·POSTECH·연세대 | 전체 24곳 + `과기원 6곳` 프리셋 | 임의의 4곳을 조용히 골라두면 학생은 자기 대학이 빠진 화면을 "일정이 없다"로 읽는다. |
| 본문 8.5~11px | 12px 하한, 대학명·마감 시각 17px | 폰트 크기 선언 49개 중 30개가 한글 UI 하한 미만이었고, 최대·최소 비가 1.41이라 크기로는 위계가 생기지 않았다. |
| `TODAY` / `UPCOMING` / `FILTER` | 한국어 | 대상이 한국 고3이고 맥락은 마감 직전의 급한 확인이다. |
| 반투명 표면 4겹 + 배경 그라데이션 | 불투명 3단계 | 합성하면 전부 같은 색으로 수렴해 층위를 못 만들면서, 같은 회색 텍스트의 대비만 화면 위치에 따라 달라졌다. |
| 다크모드 없음 | `prefers-color-scheme` 대응 | 원서 시즌에 이 앱을 여는 시간대는 야자 후다. |
| 다른 달 칸 `opacity: 0.38` | 배경색 + `9/30` 표기 | 대비 1.6:1로 떨어져 그 칸의 실제 마감이 지워졌고, 시스템 대비 강화로도 복구되지 않는다. |

## 색과 크기

- 색 토큰은 `src/styles/global.css` 최상단에 라이트 값을 `:root`에 두고, 다크는
  `@media (prefers-color-scheme: dark)`에서 **같은 토큰만 다시 정의**한다. 미디어쿼리
  안에만 존재하는 색은 하나도 없어야 한다.
- 일정 종류 8색은 전부 자기 배경(`--cat-soft`) 위에서 4.5:1 이상이다. 색만으로 구분하지
  않도록 아이콘(lucide)과 라벨을 항상 함께 쓴다.
- 글자 크기는 `--fs-xs 12` … `--fs-2xl 26` 토큰만 쓴다. 굵기는 400 / 600 / 700 세 단계뿐이다.
  폴백 폰트(맑은 고딕)는 400·700만 갖고 있어 그 사이 값은 어차피 스냅된다.
- 터치 타깃은 44px가 기본이다. 달력 일정 칩(28px)만 예외이고, 칸 자체가 날짜 선택
  핸들러를 갖고 있어 오탭이 파괴적이지 않다.

## 일부러 만들지 않은 것

- **완료 체크박스·진행 기록** — 실제로는 안 냈는데 앱이 냈다고 표시하면 마감 관리
  도구로서 아무것도 안 하는 것보다 나쁘다. 날짜가 지나면 저절로 사라지므로 기록이 필요 없다.
- **대학별 8단계 파이프라인 카드** — KAIST처럼 한 대학이 전형을 여러 개 갖는 경우
  (`admissionDetail` 44종, 대학×카테고리 중복 20조합) 대학 단위로 합치면 창의도전전형
  지원자에게 일반전형 면접 날짜를 확정된 사실처럼 보여주게 된다. 대신 "대학별 다음 마감"
  으로 **실재하는 이벤트 하나**만 보여준다.
- **면접 원문의 모집단위 자동 파싱** — `11.28(토) 11.29(일) 반도체`처럼 날짜와 모집단위의
  대응이 모호한 원문이 있다. 원문을 그대로 보여주고 경고 한 줄을 붙인다. 틀린 단정이
  원문 노출보다 나쁘다.
- **Pretendard 자가 호스팅** — 학교 와이파이에서 첫 로드를 느리게 만든다. 폰트 없이도
  크기·굵기·대비 토큰은 맑은 고딕에서 그대로 유효하다. 넣게 되면 동적 서브셋으로.
- **URL에 필터·월·다이얼로그 상태 동기화** — `/?d=`(달력 날짜)와 `/schedule?u=`(대학)
  딥링크만 둔다. 나머지는 히스토리 관리 비용 대비 이득이 적다.
