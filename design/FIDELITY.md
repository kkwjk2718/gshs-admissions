# UI 결정 기록

`calendar-concept.png` / `table-concept.png`는 초기 시안이다. 아래는 실제로 만든 것과
2026-09 개편에서 무엇을 왜 바꿨는지의 기록이다. **다음 사람이 절반만 고치는 일이 없도록,
이전 판에서 의도적으로 뒤집은 결정을 먼저 적는다.**

## 원칙

1. 화면은 "내 다음 마감이 언제 몇 시까지인가"에 먼저 답한다. 달력은 확인용 보조 화면이다.
2. 원본에 없는 정보는 만들지 않는다. 시각이 없는 71건에 18:00을 채우지 않고, 모집단위
   귀속을 추측 파싱하지 않고, 완료 여부를 기록하지 않는다.
3. 의미는 글자로 한 번 전달한 뒤에 색을 얹는다. 일정 종류는 항상 아이콘 + 라벨을 동반한다.
4. 본문 12px 하한, 대비 4.5:1 하한. `opacity`로 대비를 깎지 않는다.
5. 적게 만든다. 새 데이터 파일 0개, 새 저장 책임 0개.

## 색 — 지어내지 않는다

색은 전부 실제로 서비스 중인 캘린더에서 가져온다. 근거 없는 hex 를 새로 만들지 않는다.

| 무엇 | 어디서 |
| --- | --- |
| 중립색 (`--ink` `--muted` `--line` 계열) | Google GM2 그레이 램프 (#202124 / #3c4043 / #5f6368 / #dadce0 / #e8eaed / #f8f9fa) |
| 캔버스 `--canvas` `#f0f4f9` | Google Calendar GM3 surface-container |
| 강조 `--accent` `#0b57d0` / 다크 `#a8c7fa` | Google GM3 primary |
| 일정 8색 중 7개 | Google Calendar 이벤트 색 (Blueberry · Light Blue 700 · Tangerine · Graphite · Tomato · Basil · Grape) |
| 일정 8색 중 추천서 `#945c1f` | 카카오 톡캘린더 BROWN (공개 문서값) |
| 다크 8색 | Google 다크 테마 300 램프 |

**규칙 셋. 이걸 어기면 다시 지어낸 티가 난다.**

1. **`--cat` 은 마크 전용이다.** 3px 세로 막대, 7px 점, 16px 아이콘 획에만 들어간다.
   카테고리 라벨 글자는 `--ink` 다. 구글·애플·노션·톡캘린더 어디도 일정 색을 글자색으로 쓰지 않는다 —
   채운 칩에 대비 글자이거나, 작은 색 마크에 중립 글자 둘 중 하나다.
2. **파랑은 오늘·선택·기본 버튼·링크 넷뿐이다.** 일정 색과 섞지 않는다. 표 머리띠, 표 hover 틴트,
   선택된 칸 채움을 전부 걷어낸 이유가 이것이다.
3. **상태색을 새로 만들지 않는다.** `--danger` = 면접, `--warn` = 추천서, `--ok` = 최종 발표와
   같은 hex를 쓴다. 그래서 앱 전체가 **일정 8색 + 파랑 1색**으로 끝난다.

Google 의 노랑(Banana `#f6bf26`)은 흰 배경 1.69:1 이라 3px 막대에서 보이지 않아 뺐고,
그 자리를 카카오 BROWN(5.51:1)이 대신한다. Peacock `#039be5` 는 `--canvas` 위 2.79 라
같은 램프의 한 단계 아래 Light Blue 700 `#0288d1` 로 내렸다.

라이트·다크 전부 검산했다 — 글자 쌍은 모두 4.5:1 이상, 카테고리 마크는 surface / surface-2 /
canvas 세 배경 모두에서 3:1 이상(라이트 최저 3.15 서류, 다크 최저 3.77 원서).

남은 약점: 라이트에서 `--accent`(#0b57d0)와 원서 접수(#3f51b5)의 명도가 거의 같다(1.08).
형태로 갈랐다 — 파랑은 항상 **채워진 것**(오늘 원, 버튼, 탭 밑줄)이고 카테고리는 **가는 마크**다.
거슬리면 원서 접수와 추가 합격 발표의 `--cat` 값을 서로 바꾸면 된다(추합은 12월에만 뜬다).

2형 색각에서 추천서(갈색)와 최종 발표(초록)가 1.02:1 로 붙는다. 빨강·주황·갈색·초록이
올리브로 수렴하는 건 어느 팔레트로도 못 피한다. 두 색은 카테고리 순서상 인접하지 않고,
아이콘이 다르고, 어디서나 라벨 글자가 1차 채널이다.

## 크기

- 테마는 `index.html` 의 인라인 스크립트가 첫 페인트 전에 `data-theme` 을 채우고,
  헤더의 전환 버튼이 같은 경로를 쓴다. CSS 는 `:root` 가 라이트, `:root[data-theme="dark"]`
  가 다크다. 스크립트가 죽었을 때를 위한 `@media (prefers-color-scheme: dark)` 안전망도 둔다.
- 글자 크기는 `--fs-xs 12` … `--fs-2xl 26` 토큰만 쓴다. 굵기는 400 / 600 / 700 세 단계뿐이다.
  폴백 폰트(맑은 고딕)는 400·700만 갖고 있어 그 사이 값은 어차피 스냅된다.
- 터치 타깃은 44px가 기본이다. 달력 일정 칩(28px)만 예외이고, 칸 자체가 날짜 선택
  핸들러를 갖고 있어 오탭이 파괴적이지 않다.

## 달력 칸 높이

24곳을 다 켜면 12월 격자가 993px가 되어 1366×768에서 한 달이 한 화면에 안 들어온다.
줄당 대학 수에 상한을 두고 "외 N곳"으로 접으면 700px 아래로 내려가지만, **접지 않는다.**
이 화면의 요구가 "좁은 칸에서도 다 보이게"이고, 원본 종이 달력도 12월 18일 칸에 22곳을
전부 적어 페이지의 40%를 쓴다. 대신:

- 실제로 쓰는 상태에서는 문제가 아니다. 과기원 6곳이면 같은 12월 격자가 **548px**로 화면에 들어온다.
- 옆 패널은 달력 열이 140px 아래로 내려가지 않는 폭(1340px 이상)에서만 붙인다.
  1200px에 붙였더니 1199px(열 162px)보다 오히려 좁아지는 구간이 생겼다.

## 일부러 만들지 않은 것

- **완료 체크박스·진행 기록** — 실제로는 안 냈는데 앱이 냈다고 표시하면 마감 관리
  도구로서 아무것도 안 하는 것보다 나쁘다. 날짜가 지나면 저절로 사라지므로 기록이 필요 없다.
- **대학별 8단계 파이프라인 카드** — KAIST처럼 한 대학이 전형을 여러 개 갖는 경우
  (`admissionDetail` 44종, 대학×카테고리 중복 20조합) 대학 단위로 합치면 창의도전전형
  지원자에게 일반전형 면접 날짜를 확정된 사실처럼 보여주게 된다. 대신 "대학별 다음 마감"
  으로 **실재하는 이벤트 하나**만 보여준다.
- **면접 원문의 모집단위 자동 파싱** — `11.28(토) 11.29(일) 반도체`처럼 날짜와 모집단위의
  대응이 모호한 원문이 있다. 원문을 그대로 보여주고 경고 한 줄을 붙인다. 틀린 단정이
  원문 노출보다 나쁘다.
- **Pretendard 자가 호스팅** — 학교 와이파이에서 첫 로드를 느리게 만든다. 폰트 없이도
  크기·굵기·대비 토큰은 맑은 고딕에서 그대로 유효하다. 넣게 되면 동적 서브셋으로.
- **URL에 필터·월·다이얼로그 상태 동기화** — `/?d=`(달력 날짜)와 `/schedule?u=`(대학)
  딥링크만 둔다. 나머지는 히스토리 관리 비용 대비 이득이 적다.
